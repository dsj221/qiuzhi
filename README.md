# 求职 Agent

面向求职者本人的本机工作台：**我的简历 → 岗位匹配 → 投递跟进 → 面试准备**。

从同级“简历候选Agent”复用可用基础能力，在此目录独立改造。原项目的代码、数据库、密钥、配置和运行环境均未改动；本项目不读取原简历库。

## 启动

Python 3.9+、macOS/zsh。在本目录运行：

```sh
zsh run.sh
```

打开 [求职工作台](http://127.0.0.1:8766)。新项目使用 **8766** 端口，原项目仍使用 **8765**，可以同时运行。按 Ctrl+C 停止，重启会保留数据。

首次启动会创建独立 `.venv` 并安装 `requirements.lock`。本次环境无法联网，已将原环境安装的依赖复制到本项目虚拟环境（不包含原应用的可编辑导入路径），当前项目可离线启动。

## 使用

1. **我的简历**：粘贴经历，或导入文本 PDF、DOCX、UTF-8 TXT。文件上限10MB，PDF最多30页；扫描件、图片、旧DOC请先转为文字。检查正文后保存，常见联系方式与敏感属性经规则脱敏，不保存上传的原文件。
2. **岗位匹配**：手动收藏目标岗位、公司、链接与JD。要求每行填写 `要求 | 关键词1,关键词2 | 权重1–5`，最多8条。点击“开始匹配”查看逐项结论与简历原文。岗位要求作为快照保存，需调整时可重新收藏。
3. **投递跟进**：记录已收藏、已投递、沟通中、面试中、收到Offer、已结束；添加跟进日期和备注。到期项会标记为待跟进。可手动记录状态，或接收已确认投递批次的平台回执；修改跟进状态本身不会触发投递，日期不会自动发送通知。
4. **面试准备**：先完成岗位匹配，再生成基于要求和简历证据的案例问题、准备提示、反问清单和初次沟通草稿。没有证据时明确标注，不补造经历。沟通草稿可复制后自行发送。回答练习文本仅留在当前页面，刷新或重新生成清单会丢失，请另行保存需要保留的内容。

空工作台可点击“体验演示”，创建虚构简历与岗位；已有数据时不允许覆盖载入。本机保留了虚构演示记录，以及本次通过扩展实际导入的BOSS岗位和已确认的聊天岗位档案。

### 按岗位筛选条件搜索并投递

1. 在“岗位匹配”填写目标岗位、城市、月薪下限、必需关键词、排除公司和匹配阈值。设置每组最多读取岗位数（1–20）与每次最多搜索组合数（1–20），点击“保存并打开 BOSS 搜索”。
2. 在 BOSS 扩展使用已验证的岗位列表配置并保存，第⑤区点击“按已保存条件搜索并筛选”。扩展会按“岗位 × 城市”依次打开官方搜索列表，读取每组首屏详情，跨列表去重，符合项按设置收藏。搜索计划展示本次覆盖范围，不自动翻页。
3. 回工作台勾选符合条件的岗位，填写 BOSS 显示账号及准确简历名称，预览投递批次并核对具体目标和文件，再确认加入执行队列。
4. 在扩展刷新已确认批次并执行。每个目标会回到采集时的搜索列表重新定位和核验。只有明确的新平台回执才记为简历已投递；招呼及简历发送请求单独记录。

默认最多搜索5组、每组10个岗位；账号变化、切换标签、修改筛选条件、出现验证或结果不明时停止。未配置城市代码会明确提示，使用全国搜索后仍按意向城市严格筛选；可在计划中看到搜索链接。真实页面附件简历选择器须完成现场诊断，未验证时扩展会阻止文件发送。薪资字体混淆或 JD 不完整时放入待核对，不会猜测后投递。

0.6.0已修复列表页进入真实聊天的切换：先定位唯一联系人，再核对岗位和公司。BOSS点击“立即沟通”可能发送平台默认招呼；会话已有本人发送记录时，不追加模板，记录为已有沟通。扩展第⑤项可以“定位并核对第①项所选岗位会话（不发送）”，并补查停在打开沟通阶段的旧结果。已用智慧树真实会话核对成功，未新增发送。

更新后需重启工作台，在 Chrome 扩展管理中重新加载本项目扩展，再刷新 BOSS 页面。已核对真实 BOSS 搜索链接中关键词及上海、合肥城市的生效；搜索队列和跨列表投递通过自动化模拟验证，尚未执行真实投递。

### 自动获取岗位 JD（BOSS）

更新后重启 `zsh run.sh`，在 Chrome 扩展管理中重新加载本项目扩展，再刷新 BOSS 页面。扩展第③区默认开启“建档或绑定聊天时自动补全缺失 JD”：从聊天建立档案或绑定缺少 JD 的聊天岗位时，会尝试获取完整岗位正文。也可选中已有 BOSS 岗位，点击“自动获取所选岗位 JD”手动重取。

优先读取浏览器中已展开的详情，否则使用岗位已保存的官方链接或当前聊天中的岗位链接读取详情 HTML。浏览器可沿用平台登录会话，扩展不读取或保存 Cookie 值，也不执行下载页面的脚本。只接受名称、公司和已知岗位 ID 对应的正文；登录验证、正文缺失或页面结构变化会显示失败，可在浏览器打开对应完整详情后重试。

补全直接更新原岗位，保留投递进度、跟进日期及备注。JD 内容变化后清除旧匹配，生成待校对的要求草稿，相关旧筛选和待执行批次需要重新核对；相同正文重复获取保留已校对要求与匹配结果。新增流程通过本机虚构页面测试，尚未在真实 BOSS 页面联调。

## 匹配与模型

未配置模型时使用继承的保守规则：仅识别关键词和显式否定，命中关键词只表示“部分相关”。参考分由已验证维度加权计算，缺少证据的维度不计零分；全部未验证时不生成分数。它不代表录用概率，也不能认证实际能力。

编辑或删除简历后，全部旧匹配报告会清除，面试准备也需要重新匹配。每份报告记录简历版本。

如需模型辅助，把 `.env.example` 复制为 `.env`，设置兼容 Chat Completions 的 `MODEL_BASE_URL`、`MODEL_NAME`、`MODEL_API_KEY` 后重启。模型需支持 `/chat/completions` 与 JSON 输出；可以从 `.env.example` 查看格式。三个字段全部设置后，匹配时会把脱敏后的简历和岗位要求发给你配置的服务。模型输出须通过原文证据校验；请求或输出异常会降级为本地规则并显示提示。本次未调用真实模型服务。

面试问题和沟通草稿目前使用可解释的本地模板，页面明确标注为模板。

## 数据与范围

- 数据保存在本项目 `data/job-agent.sqlite3`，工作台令牌为本项目独立生成的 `data/admin.token`，与原项目无共享。
- 本机单用户运行，只监听 `127.0.0.1`；数据库文件不提供全盘加密。不要分享 `.env`、`data/` 或含个人信息的副本。
- 规则脱敏不能保证识别所有隐含个人信息，导入后请检查内容。删除简历会清除匹配报告，但保留岗位、投递备注与状态；备注中自行填写的个人信息需自行删除或删除整条岗位。系统备份与快照另行管理。
- BOSS连接器已安装并配对，真实求职岗位列表已验证读取和导入。工作台提供登录弹窗、连接管理、扩展下载和导入岗位的要求校对。真实聊天的可见消息快照同步、从聊天建立岗位，以及逐条确认填入草稿，均已在Chrome联调通过。新增按条件搜索与已确认批次执行；搜索参数已在真实页面核对，批次执行仅完成模拟验证，未发送真实简历。详见 [BOSS接入与联调](docs/BOSS接入与联调.md)。
- 未复制原项目 `data/`、`.env`、Chrome配对、构建产物、招聘端部署、候选人会话数据。
