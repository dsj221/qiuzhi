# 求职 Agent

面向求职者本人的本机工作台：**我的简历 → 岗位匹配 → 投递跟进 → 面试准备**。

从同级“简历候选Agent”复用可用基础能力，在此目录独立改造。原项目的代码、数据库、密钥、配置和运行环境均未改动；本项目不读取原简历库。

## 启动

macOS 上双击「开启工作台自动运行.command」安装当前用户的登录服务。后台程序、日志和数据放在 `~/Library/Application Support/local.qiuzhiagent.workbench/`。项目的 `data` 目录会链接到同一份数据，保留聊天记录、扩展配对和模型设置。看到「登录服务已接管 8766」即可关闭终端，之后可直接打开 http://127.0.0.1:8766 。如需停用自动运行，在终端执行 `launchctl bootout gui/$(id -u)/local.qiuzhiagent.workbench`，再移除 `~/Library/LaunchAgents/local.qiuzhiagent.workbench.plist`。

Python 3.9+、macOS/zsh。在本目录运行：

```sh
zsh run.sh
```

打开 [求职工作台](http://127.0.0.1:8766)。新项目使用 **8766** 端口，原项目仍使用 **8765**，可以同时运行。按 Ctrl+C 停止，重启会保留数据。

首次启动会创建独立 `.venv` 并安装 `requirements.lock`。本次环境无法联网，已将原环境安装的依赖复制到本项目虚拟环境（不包含原应用的可编辑导入路径），当前项目可离线启动。

## 使用

1. **我的简历**：粘贴经历，或导入文本 PDF、DOCX、UTF-8 TXT。文件上限10MB，PDF最多30页；扫描件、图片、旧DOC请先转为文字。检查正文后保存，常见联系方式与敏感属性经规则脱敏，不保存上传的原文件。
2. **岗位匹配**：手动收藏目标岗位、公司、链接与JD。要求每行填写 `要求 | 关键词1,关键词2 | 权重1–5`，最多8条。点击“开始匹配”查看逐项结论与简历原文。岗位要求作为快照保存，需调整时可重新收藏。
3. **投递跟进**：记录已收藏、已投递、沟通中、面试中、收到Offer、已结束；添加跟进日期和备注。到期项会标记为待跟进。可手动记录状态，或接收已确认投递批次的平台回执；修改跟进状态本身不会触发投递，日期不会自动发送通知。
4. **面试准备**：先完成岗位匹配，再生成基于要求和简历证据的案例问题、准备提示、反问清单和初次沟通草稿。没有证据时明确标注，不补造经历。沟通草稿可复制后自行发送。回答练习文本仅留在当前页面，刷新或重新生成清单会丢失，请另行保存需要保留的内容。

空工作台可点击“体验演示”，创建虚构简历与岗位；已有数据时不允许覆盖载入。本机保留了虚构演示记录，以及本次通过扩展实际导入的BOSS岗位和已确认的聊天岗位档案。

### 按岗位筛选条件搜索并投递


在工作台“为勾选的符合项准备投递批次”中选择已配对的连接和 BOSS 显示账号，可开启或关闭“筛选后自动打招呼”。开启后，在扩展第⑤项完成搜索或采集，或在“全流程自动运行”中选择招呼模式，都会对本轮新匹配的岗位按批发起沟通。BOSS 可能发送账号已设置的默认招呼。已沟通、待核对和过期匹配不会重新发起招呼。附件模式仍需逐批核对。更新此功能需要重启本机服务并重新加载扩展。

在已配对的 Chrome 侧栏顶部选择执行方式，开启“全流程自动运行”。首次启用时自动配对本机工作台并载入真实页面配置。打开岗位或已有聊天后，扩展核对官方岗位 ID，读取完整 JD，将当前会话的可见消息同步到本机，并依次显示五步进度。保持侧栏打开，工作台与 BOSS 在前台时运行。浏览岗位可自动导入，每天首次运行、保存新版筛选条件或更新简历后会按搜索计划重新筛选。搜索结果按每批最多 10 个新目标生成草稿，自动打开工作台核对页。一次确认覆盖本批列出的账号、目标和具体内容，扩展随后逐项执行并记录回执。默认方式为发送招呼，指定附件模式需填写准确文件名并完成平台选择器验证。关闭侧栏暂停运行，取消勾选可关闭自动化。

在扩展 0.10.0 的「自动求职」中选「发送招呼」，勾选「开启全流程自动运行」。工作台须为同一账号开启自动打招呼和 HR 回复跟进，并选择 AI 回复、保存飞书机器人。保持 BOSS 当前标签和侧栏打开。当天筛选与已批准批次完成后，扩展回到聊天页，监听联系人列表里的新未读消息，自动切换到对应会话并核对招聘方。单独使用自动聊天时，只需开启工作台的「HR 回复跟进」，保持 BOSS 聊天标签页在前台，侧栏可以关闭。人工输入框有草稿时会等待。收到 HR 来信后归档、排队发送飞书提醒、生成文字回复，再按跟进设置处理附件。已有附件回执会跳过重复发送；需要本人确认时停在 BOSS 确认框。手动操作仍可从第⑤项进入。

1. 在“岗位匹配”填写目标岗位、城市、月薪下限、可选关键词、排除公司和匹配阈值。关键词默认仅标记命中，勾选“必须命中全部关键词”后启用严格筛选。设置每组最多读取岗位数（1–20）与每次最多搜索组合数（1–20），点击“保存并打开 BOSS 搜索”。
2. 在 BOSS 扩展使用已验证的岗位列表配置并保存，第⑤区点击“按已保存条件搜索并筛选”。扩展会按“岗位 × 城市”依次打开官方搜索列表，读取每组首屏详情，跨列表去重，符合项按设置收藏。搜索计划展示本次覆盖范围，不自动翻页。
3. 回工作台勾选符合条件的岗位，填写 BOSS 显示账号及准确简历名称，预览投递批次并核对具体目标和文件，再确认加入执行队列。
4. 在扩展刷新已确认批次并执行。每个目标会回到采集时的搜索列表重新定位和核验。只有明确的新平台回执才记为简历已投递；招呼及简历发送请求单独记录。

默认最多搜索5组、每组10个岗位；账号变化、切换标签、修改筛选条件、出现验证或结果不明时停止。工作城市和可选区县直接应用于 BOSS 搜索页，无法识别的地区会提示修正。真实页面附件简历选择器须完成现场诊断，未验证时扩展会阻止文件发送。薪资字体混淆或 JD 不完整时放入待核对，不会猜测后投递。

0.6.0已修复列表页进入真实聊天的切换：先定位唯一联系人，再核对岗位和公司。BOSS点击“立即沟通”可能发送平台默认招呼；会话已有本人发送记录时，不追加模板，记录为已有沟通。扩展第⑤项可以“定位并核对第①项所选岗位会话（不发送）”，并补查停在打开沟通阶段的旧结果。已用智慧树真实会话核对成功，未新增发送。

0.6.2的“导入当前岗位”支持列表页、完整详情页和聊天页。聊天页会自动打开“查看职位”读取完整JD；勾选导入确认后点击按钮，结果直接显示在按钮旁。同一岗位不会重复创建，猎头岗位按详情中的客户公司保存。已在真实聊天和详情页验证。

更新后需重启工作台，在 Chrome 扩展管理中重新加载本项目扩展，再刷新 BOSS 页面。已核对真实 BOSS 搜索链接中关键词及上海、合肥城市的生效；搜索队列和跨列表投递通过自动化模拟验证，尚未执行真实投递。

### 自动获取岗位 JD（BOSS）

更新后重启 `zsh run.sh`，在 Chrome 扩展管理中重新加载本项目扩展，再刷新 BOSS 页面。扩展第③区默认开启“建档或绑定聊天时自动补全缺失 JD”：从聊天建立档案或绑定缺少 JD 的聊天岗位时，会尝试获取完整岗位正文。也可选中已有 BOSS 岗位，点击“自动获取所选岗位 JD”手动重取。

优先读取浏览器中已展开的详情，否则使用岗位已保存的官方链接或当前聊天中的岗位链接读取详情 HTML。浏览器可沿用平台登录会话，扩展不读取或保存 Cookie 值，也不执行下载页面的脚本。只接受名称、公司和已知岗位 ID 对应的正文；登录验证、正文缺失或页面结构变化会显示失败，可在浏览器打开对应完整详情后重试。

补全直接更新原岗位，保留投递进度、跟进日期及备注。JD 内容变化后清除旧匹配，生成待校对的要求草稿，相关旧筛选和待执行批次需要重新核对；相同正文重复获取保留已校对要求与匹配结果。新增流程通过本机虚构页面测试，尚未在真实 BOSS 页面联调。

## 匹配与模型

在工作台顶部打开“匹配 API”，填写自己的 DeepSeek API Key。保存后即时生效。默认服务为 `https://api.deepseek.com`，模型 ID 为 `deepseek-flash`（DeepSeek V4.1 Flash）。也可以通过服务端环境变量 `DEEPSEEK_API_KEY` 或项目的 `.env` 配置密钥，格式见 `.env.example`。

自动筛选先单独比较求职条件与岗位；方向相邻或必要条件不明时进入待核对，方向及筛选条件明确符合后才评估脱敏简历。默认符合门槛为 60 分、加权证据覆盖率 35%。核心职责和硬性资格权重为 3，明确的加分项权重为 1。覆盖不足、硬性资格待核实或分数距门槛 1–15 分时进入待核对，明确冲突可直接排除。AI 结合标题与实际职责，逐项判断方向、地点、薪资、岗位类型、公司与关键词，并引用岗位原文解释判断。工作台核对引用并按用户设置的分数和覆盖率整理结果。手动匹配可从已导入的完整 JD 识别要求，也可评估自行校对的要求。未配置、接口错误或输出结构无效时会提示原因，历史规则评分须重新匹配后才能进入新批次。

面试问题和沟通草稿目前使用可解释的本地模板，页面明确标注为模板。

## 数据与范围

- 数据保存在本项目 `data/job-agent.sqlite3`，工作台令牌为本项目独立生成的 `data/admin.token`，与原项目无共享。
- 本机单用户运行，只监听 `127.0.0.1`；数据库文件不提供全盘加密。不要分享 `.env`、`data/` 或含个人信息的副本。
- 规则脱敏不能保证识别所有隐含个人信息，导入后请检查内容。删除简历会清除匹配报告，但保留岗位、投递备注与状态；备注中自行填写的个人信息需自行删除或删除整条岗位。系统备份与快照另行管理。
- BOSS连接器已安装并配对，真实求职岗位列表已验证读取和导入。工作台提供登录弹窗、连接管理、扩展下载和导入岗位的要求校对。真实聊天的可见消息快照同步、从聊天建立岗位，以及逐条确认填入草稿，均已在Chrome联调通过。新增按条件搜索与已确认批次执行；搜索参数已在真实页面核对，批次执行仅完成模拟验证，未发送真实简历。详见 [BOSS接入与联调](docs/BOSS接入与联调.md)。
- 未复制原项目 `data/`、`.env`、Chrome配对、构建产物、招聘端部署、候选人会话数据。

### HR 回复后自动跟进

在“岗位匹配 → HR 回复跟进”选择原打招呼批次的连接，填写 BOSS 显示账号及飞书群自定义机器人的 Webhook。如开启了签名验证，请填写密钥。启用、保存后可点击“发送飞书测试提醒”。使用关键词校验时可设置关键词“求职提醒”。测试消息和正式提醒均发到该机器人的群。

保持本机服务运行，并让已登录的 BOSS 聊天页作为 Chrome 当前标签。扩展读取当前打开的会话，每 5 秒补查一次；侧栏关闭时由扩展后台接手。聊天记录可在工作台「HR 回复跟进 → 已保存的聊天记录」查看。页面已加载的双方消息按平台编号去重，打开会话时只处理尚未答复的最近一轮来信。HR 连续回复会在一次检查中合并提醒。每个岗位只自动发送一次附件。AI 模式使用已配置的模型，结合最近的双向文字记录和上次已发送的回复撰写消息，无需填写模板。模型暂时不可用时保留待回复状态并自动重试。选择固定文字模式后，“后续每轮回复文字”留空则后续仅提醒。HR 新消息的摘要保存在本机。已有附件记录、人工已接话或结果不明时，可在工作台查看跟进记录。附件请求与平台已发送回执分开显示。

跟进与批量投递均须先核对当前 HR 的来信。仅有自己的招呼、已读状态或系统提示时，扩展不会打开发送简历的入口。BOSS 使用当前附件时，留空文件名。扩展会打开「发简历」。选择「我本人点确定」后由求职者确认发送，选择自动确认后由扩展点击该弹窗的「确定」。工作台随后核对聊天中的新附件记录。指定文件模式沿用文件选择器诊断。平台如需对方同意、文件选择不唯一或缺少确认按钮，请在 BOSS 人工处理。电脑休眠或聊天页不再是当前标签时暂停检查；恢复后从上次消息继续，需能读到连续的聊天记录。
