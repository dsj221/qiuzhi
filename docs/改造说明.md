# 从简历候选 Agent 到求职 Agent

原项目：`../简历候选Agent`。目标项目：当前“求职Agent”目录。改造方向经用户确认，为求职者本人使用。

| 原项目能力 | 求职 Agent 中的用途 |
| --- | --- |
| `privacy.py` | 直接复用简历脱敏规则；没有启用原候选人手机号采集能力 |
| `store.py` | 直接复用 SQLite 事务存储，改用独立数据库 |
| `model.py` | 复用保守证据识别、权重、覆盖率、模型调用及原文校验；调整助理身份和复核提示 |
| `app.py:extract_file` | 提取到 `documents.py`，复用 PDF/DOCX/TXT 解析和大小限制 |
| 原项目启动与配置 | 采用同一依赖集合、环境变量格式，改为独立包、环境、数据和8766端口 |
| 招聘任务 / 候选人队列 | 改为个人简历、多目标岗位、证据报告 |
| 候选人会话 / HR决定 | 改为手动投递状态、跟进日期、备注和历史 |
| 招聘沟通 | 改为面试准备模板、证据提示、手动发送的沟通草稿 |

没有直接迁移招聘端扩展的HR实体和发送动作，也没有迁移 `deployments/hireflow`。后续BOSS接入复用了原扩展的侧栏配对、DOM唯一定位、输入框原生setter和共享适配器打包思路，形成独立求职端扩展；真实岗位导入已验证。没有复制任何原项目真实业务数据和私密配置。

界面沿用原项目的简洁顶部导航、卡片、双栏列表与详情结构，重新组织为“我的简历 / 岗位匹配 / 投递跟进 / 面试准备”，使用独立静态页面和接口。

`source-baseline.json` 记录开始改造时读取的原项目源文件哈希，不包含数据库、密钥、环境、缓存、构建产物或附带独立部署。运行 `scripts/check_source.py` 可再次确认这些文件内容保持不变。此校验只证明列出的源文件与基线一致，不跟踪其他进程对数据库的写入。

当前版本已实现求职端扩展、真实岗位导入、聊天同步和受控草稿填入的代码；真实岗位导入、真实可见聊天快照同步和逐次确认填入均已联调通过。聊天采用本次页面绑定与人工核对，不宣称具备平台账号ID或跨刷新身份保证。自动投递和自动发送不在当前实现中。详见 `BOSS接入与联调.md`。
